## What changed for image optimization (commit 397d7423)

Prod `/_next/image?url=/logo.png&w=96&q=75` returned **400 "The requested resource isn't a valid image"** because `sharp-linux-x64` was not installed on the target Linux host. `sharp` is a native binary per-platform — the lockfile from the Windows dev machine shipped `sharp-win32-x64` only, so `npm ci` on Linux couldn't load the right binary. The `/logo.png` references in `app/init/execute`, `app/api/init/init-activate`, and the PDF header all became invisible brand logos.

`next.config.ts` now sets `images.unoptimized: true` — `<Image>` renders the raw src instead of routing through `/_next/image`. Trade-off: no server-side resize / WebP / AVIF, slightly larger bytes on the wire (266KB logo served as-is). Long-term fix:

```bash
cd Up
rm -rf node_modules package-lock.json
npm ci --legacy-peer-deps    # install sharp-linux-x64 properly
npm run build                # MUST rebuild — .next/ embeds the previous config
npm start -- -p 4444
```

Then revert `images.unoptimized` back to `false` in `next.config.ts`. Until then the fallback keeps the brand logo visible regardless of platform.

## What changed for page_views (commits 4971ce69 + ac322a2f + 0de5ac47 + 53bd472d + b3c1d424)

Adds page-level visitor analytics to the admin dashboard. Three new StatCards on `/admin` show **今日 PV** (total page views since 00:00), **今日独立访客** (logged-in users counted by id, anonymous counted by IP — `COUNT(DISTINCT COALESCE(user_id, ip))`), and **热门页面** (top path from the last 7 days). The original "已禁用用户" StatCard moves down to the 系统统计 dl (now 6 items). Grid changes from `md:grid-cols-4` → `md:grid-cols-3` to fit 6 cards in a 3×2 layout.

**Architecture** — three pieces wired together:

1. **Schema** (`4971ce69`): new `page_views` table (id / user_id BIGINT NULL / path VARCHAR(255) / ip VARCHAR(45) / user_agent VARCHAR(255) / created_at DATETIME(3)) with 3 covering indexes (created_at / user_id+created_at / path+created_at). `user_id` has no FK so views survive user deletion (mirrors `audit_log`). Created via `initTables()` for fresh installs; `scripts/migrations/2026-07-10-page-views.sql` for existing prod (DDL is `CREATE TABLE IF NOT EXISTS` so it's safe to re-run during the wizard's migrate phase).

2. **Server-side ingestion** (`ac322a2f` + `53bd472d`): client component `PageViewTracker` posts `{path}` to `POST /api/track/pageview` on every navigation (Edge middleware can't run mysql2, so the tracker lives in the client). The route uses `withErrorHandling`, validates path starts with `/` and rejects `//`, extracts IP from `x-forwarded-for` first hop + UA slice(255), and inserts via `recordPageView()` in `lib/page-views.ts`. `lib/admin-pageviews.ts::getPageViewStats(days=7)` runs 3 SELECTs anchored to `CURDATE()`. 12 unit tests cover both functions (mock-pool pattern from `tests/unit/lib/audio-tracks.test.ts`).

3. **Client-side tracker** (`0de5ac47`): `components/PageViewTracker.tsx` is a 21-line `'use client'` component in `app/layout.tsx` (after `<ActivationGuard>`, before `<ToastViewport>`). Uses `usePathname()` + `useEffect` to fire `fetch` with `keepalive: true` (so the request completes even after tab close). Excludes `/admin`, `/api`, `/_next` prefixes to keep admin traffic out of unique-visitor counts and avoid double-logging API routes (already in `audit_log`).

**Dashboard** (`b3c1d424`): 3 new StatCards with lucide icons (`Eye` / `Users` / `FileText`), all linking to `/admin/analytics` (the detail page is a future follow-up; this plan only covers the dashboard cards). The "热门页面" value is `topPaths[0]?.path ?? '—'`.
