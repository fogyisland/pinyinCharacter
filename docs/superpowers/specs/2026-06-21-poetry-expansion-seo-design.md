# Spec: 诗词朝代扩展 + 全站 SEO (Poetry Era Expansion + Site-wide SEO)

## Goal

Two related changes driven by user requests:

1. **诗词朝代扩展**: Expand the existing `/poetry` module beyond 唐诗/宋词/元曲 to cover pre-Tang 诗体 (汉乐府, 南北朝) and 骈文 (parallel prose). Add a `form` (体裁) filter axis perpendicular to the existing category axis so users can browse "all 五绝 / 七律 / 古风 / 乐府" poems across all eras.

2. **全站 SEO 深化**: Add a coherent SEO layer across the site — dynamic sitemap, dynamic robots.txt, unique metadata + canonical URLs on every content detail page, and JSON-LD structured data (CreativeWork / Book / DefinedTerm / BreadcrumbList / Organization / WebSite with SearchAction) so search engines can produce rich results.

## Background

- `poems` table currently has ~190K rows across 唐诗 / 宋词 / 元曲. `category` is a free-form VARCHAR (no enum). Existing schema: `id, title, author, dynasty, content (JSON), paragraphs, pinyin, rhythmic, type, ...` — verified via `lib/api-poetry.ts` and `lib/poetry-types.ts`.
- `/poetry` route shows category tabs (唐诗/宋词/元曲) with search/pagination. No form filter exists.
- `/ancient` module (`docs/superpowers/specs/2026-06-20-ancient-classics-design.md`) reads from `classics` table (chunks JSON for long works). 190 books already loaded (375 in production after prod push on 2026-06-21).
- `chinese-poetry/chinese-poetry` GitHub repo has `/全汉诗/`, `/南北朝/`, `/古体诗/`, `/近体诗/` JSONs. Already the data source for 唐诗/宋词/元曲 in `scripts/build-poems.ts`.
- `guwendao.net` scraping is proven (`scripts/build-classics-guwendao.ts`, 75 books, 3021 chapters). Pattern: `https://www.guwendao.net/guwen/bookv_<bookId>.aspx` for chapter content, `https://www.guwendao.net/guwen/book_<bookId>.aspx` for index. Parses `<div class="contson">...</div>` with `<p>` and `<br/>` tags. OpenCC t2s + pinyin-pro per char.
- Next.js 15 already has `MetadataRoute.Sitemap` and `MetadataRoute.Robots` types in `app/sitemap.ts` and `app/robots.ts`. Existing `app/layout.tsx` has minimal global metadata; per-page metadata is partial.
- No JSON-LD currently injected on any page.
- `classics` table is in utf8mb4 with VARCHAR `category` (not enum); new categories like 'pianwen' are free-form.

User decisions confirmed in brainstorm (2026-06-21):
1. Scope = BOTH new dynasty poetry (汉乐府/南北朝/骈文) AND form filter on existing /poetry.
2. New data sources = chinese-poetry (汉乐府/南北朝) + guwendao.net (骈文) — mixed approach.
3. Form annotation = structural inference (五言/七言/绝句/律诗) + source `type` field merge (乐府/古风). 词曲 use 词牌名/套数 as form.
4. Form storage = denormalized single column `form VARCHAR(32)` on `poems` table, indexed. NOT a separate many-to-many table.
5. Reprocessing = one-shot script over all 190K rows. ~5–10 min.
6. UI = form chips multi-select on /poetry page (below category tabs), URL-synced `?form=...`. 骈文 stays in /ancient, not /poetry.
7. New dynasty poem storage = 诗 → `poems` table (category='汉乐府'/'南北朝'); 骈文 → `classics` table (category='pianwen').
8. SEO = 全面深化 across content detail pages; 暂不做百度站长平台集成; 不做 og:image 静态图（去掉了）。
9. SEO routes prioritized = `/poetry/[id]`, `/ancient/[slug]`, `/chars/[char]` get unique metadata + JSON-LD + canonical. Other routes get `export const metadata` static (hardcoded) — only detail pages use `generateMetadata` (dynamic per-row).
10. SEO sitemap = dynamic, split into multiple files at `/sitemap/poetry.xml`, `/sitemap/ancient.xml`, `/sitemap/chars.xml`, referenced from a `/sitemap.xml` index generated by Next.js `app/sitemap.ts` convention. Sub-sitemap routes live in `app/sitemap/poetry.xml/route.ts` etc. (Next.js 15 supports dot-in-folder for route paths).
11. Rollout = all 4 steps run on `piyin_dev` first, smoke tested in browser, then re-run on prod `piyin`.

## Design

### Part 1: Schema changes (poems)

**Existing schema** (verified 2026-06-21 on prod `piyin`):
```sql
CREATE TABLE poems (
  id INT(11) NOT NULL AUTO_INCREMENT,
  dynasty ENUM('tang','song') NOT NULL,    -- ENUM, need to ALTER
  title VARCHAR(80) NOT NULL,
  author VARCHAR(40) NOT NULL,
  form VARCHAR(20) DEFAULT NULL,           -- already exists; 189/624 filled (五言律诗/七言律诗/五言古诗/七言古诗), 435 NULL
  content JSON NOT NULL,
  pinyin JSON NOT NULL,
  appreciation TEXT,
  source VARCHAR(120),
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uniq_poem (dynasty, title, author),
  KEY idx_author (author),
  KEY idx_dynasty_author (dynasty, author)
);
```

**Required changes**:
```sql
-- 1. dynasty ENUM -> VARCHAR(16) to support 乐府(汉/魏晋/南北朝), 纳兰性德(清), 曹操诗集(魏), 辞赋(mixed)
ALTER TABLE poems MODIFY COLUMN dynasty VARCHAR(16) NOT NULL;

-- 2. Add category column for grouping (existing 'tang'/'song' rows keep their dynasty; category added fresh)
ALTER TABLE poems
  ADD COLUMN category VARCHAR(32) DEFAULT NULL AFTER dynasty,
  ADD INDEX idx_category (category);

-- 3. Widen form column to accommodate 词牌名 (水调歌头 is 5 chars)
ALTER TABLE poems MODIFY COLUMN form VARCHAR(32) DEFAULT NULL;

-- 4. Add form index (existing PK only on id; no index on form)
ALTER TABLE poems ADD INDEX idx_form (form);
```

- All 4 DDLs are in-place + metadata-only in MySQL 5.7 (no table copy).
- `dynasty` values: 'tang', 'song' for existing; new values '汉', '魏', '魏晋', '南北朝', '汉末', '清', 'mixed' (for 辞赋).
- `category` values: 'tang' (existing 唐诗 — backfilled), 'song' (existing 宋词 — backfilled), '汉乐府', '古诗十九首', '魏', 'qing' (for 纳兰性德), '骈文' (for 辞赋). Existing rows: 跑一次 backfill 把 dynasty=tang → category='tang', dynasty=song → category='song'.
- `form` widening: 20→32 chars to fit `水调歌头` (5 chars), `贺新郎` (3 chars), `木兰花令` (4 chars), etc.
- `idx_form` index: 19万行后单列 cardinality 8-100 仍能高效走 `WHERE form = ?`.
- No change to `classics` table. 骈文 (训蒙骈句) uses existing schema with `category='pianwen'`.

### Part 2: Form inference algorithm

Pure function in `lib/poetry/infer-form.ts`:

```ts
type FormResult = {
  primary: string;       // '五绝' | '七绝' | '五律' | '七律' | '五言古风' | '七言古风' | '杂言古风' | '乐府' | '古风' | null
  source: 'inferred' | 'source-tag' | 'passthrough';
  confidence: number;    // 0..1
};

function inferFormFromParagraphs(paragraphs: string[]): FormResult
function resolveFormFromSource(type: string | null, rhythmic: string | null, category: string): FormResult
function mergeForm(structInferred: FormResult, sourceTag: FormResult): FormResult
```

**Structural inference rules** (paragraphs = lines of poem):
1. Filter out empty/whitespace-only lines.
2. Compute `lineLengths` = each line's character count (Chinese chars only, no punctuation).
3. Compute `lengthMode` = single value if all `lineLengths` equal, else `mixed`.
   - All 5 → `五言`
   - All 7 → `七言`
   - Mixed → `杂言`
4. Compute `lineCount` = non-empty line count.
   - 4 → `绝句`
   - 8 → `律诗`
   - Other → `古风` (with length prefix)
5. Combine: `五言` + `4 lines` → `五绝`; `七言` + `4 lines` → `七绝`; `五言` + `8 lines` → `五律`; `七言` + `8 lines` → `七律`; `五言` + `>8 lines` → `五言古风`; etc. `杂言` always → `杂言古风`.
6. Confidence = 1.0 for canonical (4/8 lines, uniform 5/7); 0.7 for 6 lines (古风 candidate); 0.5 for irregular.

**Source tag rules**:
- `category='song'` + non-null `rhythmic` → passthrough `form=rhythmic` (e.g., `水调歌头`), source='passthrough'
- `category='yuan'` + `type='套数'` → form='套数'; `type='小令'` → form='小令'
- Non-null `type` from chinese-poetry (e.g., `五言古诗`, `七言绝句`, `乐府`, `古风`, `歌行`) → use as primary form, source='source-tag', confidence=1.0
- Otherwise fall through to structural inference

**Merge rule**:
- If source-tag present and structural agrees → use source-tag, confidence=1.0
- If source-tag present and structural disagrees → use source-tag, confidence=0.8
- If source-tag absent → use structural, confidence=structural.confidence

**Existing-form normalization** (run once before backfill):
- 五言律诗 → 五律
- 七言律诗 → 七律
- 五言古诗 → 五言古风
- 七言古诗 → 七言古风
- This is a 1-pass UPDATE before the inference pass. Ensures the merged result uses canonical naming throughout the table.

### Part 3: Backfill script `scripts/build-form-tags.ts`

```ts
import { inferFormFromParagraphs, resolveFormFromSource, mergeForm } from '../lib/poetry/infer-form';

// Streams poems in batches of 1000, computes form, UPDATE.
async function backfillForm({ batchSize = 1000, dryRun = false, whereFormNull = true } = {}) { ... }
```

- Reads `SELECT id, category, paragraphs, type, rhythmic FROM poems WHERE (form IS NULL OR ?)` in batches.
- For each row: build `structInferred` from `paragraphs`; build `sourceTag` from `category/type/rhythmic`; `merged = mergeForm(struct, source)`.
- If `merged.primary !== null`: queue `UPDATE poems SET form = ? WHERE id = ?`.
- Logs progress every batch: `[batch 42/191] 42000/190000 done, 39500 form-set, 2500 NULL`.
- `--dry-run` flag: compute and print stats, no UPDATE.
- Idempotent: `whereFormNull=true` (default) limits to unset rows.
- Time estimate: 190K rows × ~1ms compute = 3 min compute + 3 min DB writes = ~6 min total. Within 5–10 min target.

**4b. `scripts/build-poems-extra.ts` 流程**:
```ts
async function buildExtraPoems() {
  // 路径 1: chinese-poetry JSON (曹操诗集 + 纳兰性德)
  for (const file of CP_EXTRA_FILES) {  // 曹操诗集/caocao.json + 纳兰性德/纳兰性德诗集.json
    const raw = await fetchCP(file.path);
    const seeds = normalizePoemJson(raw);  // 兼容 `paragraphs` 和 `para` 两种 schema
    await insertPoems(seeds, { category: file.category, dynasty: file.dynasty, source: SOURCE_TAG_CP });
  }
  // 路径 2: guwendao poem scrape (乐府 + 古诗十九首 + 辞赋)
  for (const cat of GWD_POEM_CATEGORIES) {  // [{name:'yuefu', category:'汉乐府', dynasty:'汉/魏晋/南北朝'}, ...]
    const poemList = await scrapePoemList(`https://www.guwendao.net/gushi/${cat.name}.aspx`);
    for (const pid of poemList) {
      const { title, author, dynasty, content } = await scrapePoemPage(`https://www.guwendao.net/shiwenv_${pid}.aspx`);
      await insertPoems([{ title, author, paragraphs: content, type: cat.type }], { category: cat.category, dynasty, source: SOURCE_TAG_GWD });
    }
  }
  // 写 data/poems/<slug>.json (source of truth)
}

async function insertPoems(seeds, { category, dynasty, source }) {
  for (const seed of seeds) {
    const content_hash = md5(JSON.stringify(seed.paragraphs));
    const [existing] = await pool.execute('SELECT id FROM poems WHERE title = ? AND content_hash = ?', [seed.title, content_hash]);
    if (existing.length > 0) continue;  // 幂等：跳过
    const form = mergeForm(inferFormFromParagraphs(seed.paragraphs), resolveFormFromSource(seed.type, null, category));
    await pool.execute(
      'INSERT INTO poems (title, author, dynasty, category, content, paragraphs, pinyin, type, form) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)',
      [seed.title, seed.author, dynasty, category, JSON.stringify(seed.paragraphs), JSON.stringify(seed.paragraphs), JSON.stringify(seed.paragraphs.map(linePinyin)), seed.type, form.primary]
    );
  }
}
```

**scrapePoemPage 解析** (new helper in `lib/guwendao-scraper.ts`):

- Extract author/dynasty from `.sons` or `.source` element
- Return `{ title, author, dynasty, paragraphs: string[] }`

**`app/sitemap/poetry.xml/route.ts`** — 单独 sitemap 分片:
```ts
export const revalidate = 3600;

export async function GET() {
  const poems = await pool.query('SELECT id, updated_at FROM poems ORDER BY id');
  const urls = poems.map(p => `<url><loc>${SITE}/poetry/${p.id}</loc><lastmod>${p.updated_at}</lastmod><priority>0.7</priority></url>`).join('');
  return new Response(`<?xml version="1.0"?><urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">${urls}</urlset>`, { headers: { 'Content-Type': 'application/xml' } });
}
```

- 19万行 → 整 sitemap ~10MB 字符串（协议允许多文件，单文件限制 50MB / 50000 URL）
- 用单个 route 而不是分页，避免 sitemap index 复杂
- `revalidate=3600` = Next.js 缓存 1 小时，爬虫高频访问不击穿 DB

    twitter: { card: 'summary', title: poem.title, description: desc },
  };
}

    author: { '@type': 'Person', name: poem.author },
    inLanguage: 'zh-CN',
    isPartOf: { '@type': 'Book', name: dynastyLabel(poem.dynasty) },
    text: poem.paragraphs.join('\n'),
  };
}

export function buildBook(classic: Classic) {
  return {
    '@context': 'https://schema.org',
    '@type': 'Book',
    name: classic.title,
    author: { '@type': 'Person', name: classic.author || '佚名' },
    inLanguage: 'zh-CN',
    datePublished: classic.era,
  };
}

export function buildDefinedTerm(char: Char) {
  return {
    '@context': 'https://schema.org',
    '@type': 'DefinedTerm',
    name: char.char,
    description: char.meaning_zh,
    inLanguage: 'zh-CN',
  };
}

export function buildBreadcrumbList(items: { name: string; url: string }[]) { ... }
export function buildOrganization(site: SiteConfig) { ... }
export function buildWebSite(site: SiteConfig) {
  return {
    '@context': 'https://schema.org',
    '@type': 'WebSite',
    name: '字·韵',
    url: SITE_URL,
    potentialAction: {
      '@type': 'SearchAction',
      target: { '@type': 'EntryPoint', urlTemplate: `${SITE_URL}/search?q={search_term_string}` },

}

### Risks & Mitigations

| Risk | Mitigation |
|---|---|
| raw.githubusercontent.com 网络阻塞（已发生 2026-06-20） | build-poems-extra.ts 先 HEAD 验路径；fail 立即 abort + clear error |
| Form 推断误判（如 七言古风 被判七绝） | minimum 置信度 0.7；6 行以上才标古风；fallback 到源 type |
| 词牌名 form 枚举爆炸（数百个） | 只显示 top 30 + 搜索框；不强制全显示 |
| 19万行 sitemap 单文件 10MB | 协议允许 50MB；如超限可加 lastmod-based 分片 |
| JSON-LD 字段错误 | 严格单测 snapshot；CI 跑 Google Rich Results 校验（可选） |
| 骈文 长篇抓取超时 | 沿用 G6 split 卷模式 |
| ALTER TABLE 在大表锁表 | MySQL 5.7 ADD COLUMN = in-place + instant；先在 dev 验证 |
| SEO 改动破坏 RSC 缓存 | 详情页 generateMetadata 改 cache 策略；用 revalidate 控制 |
