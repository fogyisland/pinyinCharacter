# Admin Analytics Foundation Design (Wave 1 of 3)

> **For agentic workers:** This spec is Wave 1 of a 3-wave admin/overview redesign. Wave 2 (`/admin/analytics` detail page) and Wave 3 (`/admin` overview redesign + anomaly panel) will be spec'd separately after Wave 1 ships and is verified. Only Wave 1 is in scope here.

**Goal:** Establish the shared foundation (time-range filter, chart components, recent-activity query) that Wave 2 and Wave 3 will compose on, without yet touching any admin UI page.

**Architecture:** URL-driven `?range=` parsed server-side → SQL helper; recharts-based chart component library; union-flavored recent-activity query merging audit_log + downloads + ai_logs. No UI changes in this wave — verification is unit tests + temporary dev-only mount page.

**Tech Stack:** Next.js 15.5.19 App Router + React 19 + mysql2/promise + recharts ^2.12.0 (new dep) + Tailwind + lucide-react.

## Wave 1 — Detailed Design

### Architecture

```
[Browser URL: /admin/analytics?range=30d]
  ↓
[Server Component] searchParams.range → '1d'|'7d'|'30d'|'90d'
  ↓
[lib/admin-range.ts::parseRange()] → Range (with safe default)
  ↓
[lib/admin-range.ts::rangeToSinceClause()] → { sql, params }
  ↓
[Business query, e.g. getPageViewStats] uses sinceClause for time filter
  ↓
[Data series] → recharts data prop → SVG render

[Concurrent: lib/admin-activity.ts::getRecentActivity(limit)]
  → 3 parallel pool.query() on audit_log + downloads + ai_logs
  → JS merge + sort + slice + map to Chinese summary
```

### Data Flow — Recent Activity

| Source table | Columns pulled | Maps to ActivityItem |
|---|---|---|
| `audit_log` | `id, created_at, action, target_type, target_id, user_id` | `type='audit'`, summary localized via action→中文 map, `href=/admin/audit?focus=<id>` |
| `downloads` | `id, created_at, user_id, char_id, worksheet_slug` | `type='download'`, summary = "下载 <worksheet_slug 或 char 名>", `href=/admin/downloads` |
| `ai_logs` | `id, created_at, user_id, feature, status` | `type='ai'`, summary = "AI <feature中文> <ok/err>", `href=/admin/ai?focus=<id>` |

**Query strategy** — 3 independent `pool.query()` in `Promise.all` + JS merge:

```ts
const perSourceLimit = Math.max(10, (limit ?? 10) * 2);
const [audits, downloads, ais] = await Promise.all([
  pool.query(`SELECT ... FROM audit_log ORDER BY created_at DESC LIMIT ?`, [perSourceLimit]),
  pool.query(`SELECT ... FROM downloads ORDER BY created_at DESC LIMIT ?`, [perSourceLimit]),
  pool.query(`SELECT ... FROM ai_logs ORDER BY created_at DESC LIMIT ?`, [perSourceLimit]),
]);
const merged = [...audits, ...downloads, ...ais]
  .sort((a, b) => +b.created_at - +a.created_at)
  .slice(0, limit ?? 10)
  .map(rowToActivityItem);
return merged;
```

`perSourceLimit = max(10, limit*2)` prevents any single source from squeezing others out of the top-N.

### SSR / CSR Boundary

recharts uses `ResponsiveContainer` which reads `window` — SSR throws `ReferenceError: window is not defined`.

**Fix** — all chart components are `'use client'` + render placeholder until mount:

```tsx
'use client';
import { useEffect, useState } from 'react';
import { ResponsiveContainer, LineChart, Line, XAxis, YAxis, Tooltip } from 'recharts';

export function TrendChart({ series, height = 240, yLabel, formatValue }: TrendChartProps) {
  const [mounted, setMounted] = useState(false);
  useEffect(() => setMounted(true), []);
  if (!mounted) return <div style={{ height }} className="bg-muted/30 rounded animate-pulse" />;
  // actual recharts JSX
}
```

Why not `next/dynamic({ ssr: false })`:
- Avoids Suspense boundary complexity
- Single component file, no async loading flash
- Server still outputs meaningful `<div>` placeholder

### Error Handling

| Failure | Handling |
|---|---|
| `parseRange` non-standard value | Returns `DEFAULT_RANGE='7d'`, no throw |
| `getRecentActivity` query fails | Whole `Promise.all` rejects; server component catches → returns `[]` + logs error, UI shows "暂无活动" |
| recharts receives empty series | Component renders `<EmptyChart msg="暂无数据" />` (internal helper) |
| `formatValue` callback throws | Try/catch fallback to `String(v)` |

## Risks / Notes

- **Bundle size**: recharts adds ~30-40KB gzipped after tree-shaking, only loaded on `/admin/analytics` and `/admin` (Wave 2/3). Normal user routes unaffected.
- **3-query merge cost**: `getRecentActivity(10)` runs 3 SELECTs, each with `LIMIT max(10, limit*2)=20` + ORDER BY `created_at` index scan. Sub-100ms typical; if slow, can switch to single SQL UNION with manual column alignment later.
- **Chinese summary maintenance**: action→中文 map lives in `lib/admin-activity.ts::rowToActivityItem`. New audit_log actions need map entries (forgotten = silent "unknown action" string). Documented in code comment.
- **recharts version**: pinning to `^2.12.0` — v3 has breaking changes (deprecates ResponsiveContainer size prop). Hold at v2.
- **Pre-existing integration test failure**: `tests/integration/scripts/import-hsk.test.ts` fails with "Access denied for user 'root'@'localhost'" — not Wave 1 regression, documented separately.
- **No REDEPLOY doc bump**: Wave 1 is library-only, no production-deployable surface change. Wave 2/3 will bump REDEPLOY-2026-07-09.md.
